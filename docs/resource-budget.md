# ATK-DNN647 资源预算实测（含 xTS 可行性分析）

> 日期：2026-11-21　板卡：ATK-DNN647（STM32N647，Cortex-M55，**无片内 Flash**）
> 所有数字均为真机实测，非估算。

---

## 一、两条独立的限制（关键：别把它们混为一谈）

本平台的资源约束有两条，**同时**成立：

| 限制 | 数值 | 性质 | 后果 |
|---|---|---|---|
| **A. Boot ROM 镜像上限** | **约 123KB**（125,952B 可行 / 126,976B 失败） | 串口烧录通道的限制 | 镜像大了**根本启动不了**，串口 0 字节输出 |
| **B. FLEXRAM 窗口** | 240KB（0x34180240 ~ 0x341BC240 = 245,760B） | 物理内存 | 代码 + 数据 + 栈 + 堆共享这一块 |

**A 比 B 更紧**：就算 FLEXRAM 放得下，镜像超过 123KB 也起不来。

---

## 二、Boot ROM 上限的实测过程

用固定固件 + 尾部填充的方式二分定位（填充到 `.bss` 之后的空闲区，不影响正常运行）：

| 镜像大小 | 块数 | 结果 |
|---|---|---|
| 102,924B | 402 | ✅ 正常启动 |
| 112,640B (110KB) | 440 | ✅ |
| 117,760B (115KB) | 460 | ✅ |
| 122,880B (120KB) | 480 | ✅ |
| 123,904B (121KB) | 486 | ✅ |
| 124,928B (122KB) | 490 | ✅ |
| **125,952B (123KB)** | **494** | ✅ **可行** |
| **126,976B (124KB)** | **498** | ❌ **0 字节输出** |
| 128,000B (125KB) | 500 | ❌ |
| 133,120B (130KB) | 523 | ❌ |
| 174,080B (170KB) | 683 | ❌ |
| 204,800B (200KB) | 803 | ❌ |

**失败特征**：`downloaded N blocks, fails=0`、`start ACKs: 121 121`（ROM 已接受并跳转），
但 boot trace **完全为 0 字节** —— 连最早的标记都没有。

**上限 ≈ 125,952B（约 123KB）**，即 494 个 256 字节块。

## 四、xTS 全量为什么不可能

| 配置 | 镜像 | 对比 123KB 上限 |
|---|---|---|
| xTS 全套（cmocka + ostest + getprime + mm + scanftest + fstest + ramtest + driver_test） | **172,664B** | **超出 40%，绝对起不来** |

即使能塞进 FLEXRAM（240KB），也过不了 Boot ROM 这一关。

**因此 xTS 必须分批烧录测试**，每批镜像控制在 **≤120KB**（留 3KB 余量）。

---

## 五、关键优化：把 idle 栈从 32KB 降到 8KB

**动机**：idle 栈原设 32,768B，而 idle 任务只做看门狗和内存回收，
NuttX 默认值通常是 1~2KB，8KB 已非常宽裕。

| 项 | 32KB 栈 | 8KB 栈 | 变化 |
|---|---|---|---|
| 镜像 | 102,924B | 102,924B | 不变（栈不占 ROM） |
| **堆** | **101,096B** | **125,672B** | **+24,576B** |
| `ps` 显示 idle 栈 | 32,744B | 8,168B | — |

**这一项优化直接决定了 xTS 能否跑通**：

- 优化前 xts 配置堆约 87KB → `mm` 测试跑到中途**停滞不动**（150 秒无进展）
- 优化后 xts 配置堆 111,872B → **`mm` 输出 `TEST COMPLETE`，通过**

回归验证：nsh 配置改 8KB 后，一键自测 **14 项全过**（启动 / NSH / free / ps / userleds / LED 全部子命令）。

## 六、可行的 xTS 分批方案

每批 ≤120KB，建议按此顺序：

| 批次 | 内容 | 镜像 | 状态 |
|---|---|---|---|
| 第 1 批 | cmocka/testsuites、mm、fstest、ramtest、driver_test、dev_gpio | 115,880B | ✅ **已构建并验证**：`mm` → `TEST COMPLETE` |
| 第 2 批-a | getprime | 104,192B | ✅ **已跑通**：找到 1230 个素数，540ms |
| 第 2 批-b | scanftest（+ tmpfs + 浮点） | 120,416B | ✅ **已跑通**：OK 164 / FAILED 0 |
| 第 2 批-c | ostest | **172,988B** | ❌ **超上限 40%，放不下** |
| — | Flash 类用例（1.2.4 / 1.3.5） | — | ❌ 不适用：本板无片内 Flash |

## 八、结论

**单个固件跑全套 xTS：不够。** 卡在 Boot ROM 的 123KB 镜像上限，超出 40%。

**分批跑：够，而且已经跑通第一批。** 关键前提是
「idle 栈降到 8KB」——它把堆从 87KB 提到 111KB，`mm` 测试因此从停滞变为通过。

后续做 xTS 时，每批构建后先看两个数：
1. **镜像 ≤120KB**（否则根本起不来）
2. **`free` 的 Umem total ≥100KB**（否则内存类测试会停滞）
