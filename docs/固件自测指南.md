# ATK-DNN647 固件自测指南

> 面向：想在 5 分钟内确认板子 + 固件是否正常的人
> 环境：macOS，串口 `/dev/cu.usbserial-1420`

---

## 0. 先记住三件事（否则一定踩坑）

| # | 要点 | 说明 |
|---|---|---|
| 1 | **picocom 的校验位用 `n`，不是 `e`** | 板子 USART 是 9 位字长，主机用 8N1 反而能正常收发；实测 `--parity e` 收不到任何数据。 |
| 2 | **退出后可以直接重连，不必重烧** | 正常退出 picocom 不复位板子，固件仍在 SRAM。只有按 REST / 拔 USB / 重新烧录才会丢。重连报 lock 冲突就等 2~3 秒。 |
| 3 | **烧录和 picocom 要串在一条命令里** | 用 `;` 连接，烧完立刻进 picocom，中间不要手动开关串口。 |

## 1. 最快确认：一条命令（推荐）

```bash
cd ~/.zcode/workspace/8d40629c-1cb8-4a0a-9d30-df7584ef9f9e/n6-test

python3 nsh_verify.py /dev/cu.usbserial-1420 nuttx_bootrom.bin 341806c1 6

**正常输出**（末尾必须是 `RESULT: ALL PASS`）：

```

start ACKs: 121 121
boot trace: 90B  NuttShell=True  nsh>=True

**每项在验证什么：**

| 检查 | 说明 |
|---|---|
| `downloaded N blocks, fails=0` | 串口烧录全部块被 Boot ROM 接受 |
| `start ACKs: 121 121` | Boot ROM 确认启动（0x79 = 'y'） |
| `boot trace: 90B  NuttShell=True` | 固件真的跑起来了；90B = LED 注册日志 + 欢迎语 + 提示符（调试探针已清理，清理前为 121B 且含 `mount failed` 错误） |
| `help` | 命令解析器工作 |
| `uname -a` | 内核正常，且能看到构建时间 |
| `ps` | 调度器在跑，能看到任务列表（`STACK COMMAND` 表头） |
| `ls /dev/userleds` | **LED 驱动注册成功**（关键：证明用户态驱动链路通） |

> ⚠️ 脚本已内置**负向检查**：任何命令返回 `command not found` 会直接判失败，
> 不会像早期版本那样被 `nsh>` 蒙混过关。

## 2. 物理确认：亲眼看 LED（最有说服力）

UART 只能证明软件链路通，**LED 亮灭才能证明 GPIO 硬件路径通**。

用交互模式，烧录后串口不关闭，可以自己敲命令：

```bash
python3 n6_console.py /dev/cu.usbserial-1420 nuttx_bootrom.bin 341806c1 6
```

烧录 + 自动验证后会进入 `n6>` 提示符，直接输入：

```
n6> leds 0 on        ← 核心板 LED0 (PG10) 亮
n6> leds 0 off       ← 灭
n6> leds 1 on        ← 底板 LED1 (PE10) 亮
n6> leds 1 off       ← 灭
n6> leds 0 blink     ← 闪烁几秒
n6> leds -h          ← 看用法
n6> exit             ← 退出（板子继续运行）
```

**预期**：两颗 LED 各自独立受控 → 说明 `st_userled.c` 的 lowerhalf、GPIO 时钟、
MODER 配置、active-low 极性全部正确。

## 4. 手动连串口（推荐方式，已验证）

一条命令完成「烧录 + 进 picocom」：

```bash
python3 -u n6_flash.py /dev/cu.usbserial-1420 nuttx_bootrom.bin fsbl.bin 341806c1 6 ; \
picocom -b 115200 --parity n -d 8 --stopbits 1 -f n --noinit \
         --lower-dtr --lower-rts /dev/cu.usbserial-1420
```

看到 `Terminal ready` 后，**敲一次回车**就会出现 `nsh>`，然后正常敲命令：

```
nsh> uname -a
nsh> ls /dev
nsh> leds 0 on          ← 看核心板灯
```

| 参数 | 值 | 注意 |
|---|---|---|
| `--parity` | **`n`** | **必须用 `n`。用 `e` 收不到任何数据**（实测） |
| `--noinit` `--lower-dtr` `--lower-rts` | — | 三个都要带 |

**退出**：`Ctrl+A` 然后 `X`。

> ✅ **退出后不必重烧**：正常退出 picocom 不复位板子，固件仍在 SRAM，
> 再次执行同一条 picocom 命令就能继续操作。
> 固件只在按 REST 键、拔插 USB、或重新烧录时丢失。
> 重连若报 `cannot lock`，等 2~3 秒再连。

## 5. 常见现象与判断

| 现象 | 含义 | 处理 |
|---|---|---|
| 满屏乱码 / 方块 | 校验位参数不对 | 改成 `--parity n`（实测 `e` 收不到数据） |
| 完全无输出，`boot trace: 0B` | 固件超限或损坏 | 重新烧录；确认固件 <120KB |
| 打开工具后没反应 | 工具拉 DTR/RTS 复位了板子，SRAM 固件丢失 | 加 `--noinit`；重烧 |
| 只有 `nsh>` 无欢迎语 | 欢迎语在烧录瞬间就打完了 | 发空回车 |
| `leds: command not found` | 烧的不是含 LED 功能的固件 | 用 `nuttx_bootrom.bin`（或 `known_good_led_demo_0124/`） |
| `free: command not found` | 固件不含 `free`（旧版本） | 用最新 `nuttx_bootrom.bin`（20:16 之后构建的含 `free`） |
